💡 What
Fixed an N+1 query issue in the `manage_marketing_campaigns` method within `src/blank_business_builder/level6_agent.py`. The `_needs_marketing_campaign` function was changed to accept a pre-fetched set of business IDs rather than performing a database query for each individual active business.

🎯 Why
When executing autonomous marketing campaign management, `_needs_marketing_campaign` previously made a separate query for every single active business to check if they had a recent campaign. This resulted in O(N) database queries where N is the number of active businesses, causing unnecessary database load and latency as the number of businesses grows.

📊 Impact
Reduces the number of database queries in `manage_marketing_campaigns` from O(N) to O(1) for active businesses, significantly lowering DB load and processing time for this routine.

🔬 Measurement
Review the SQL queries generated during the execution of `manage_marketing_campaigns`. Instead of a query per active business, there should now be exactly two queries: one to fetch all active businesses, and a second to bulk-fetch the recent marketing campaigns for those businesses. Tests can be run locally using a customized test runner, although this environment's mocked setup continues to have pre-existing setup errors in the suite as expected.
